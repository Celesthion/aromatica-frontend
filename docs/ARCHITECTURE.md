# Архитектура фронтенда

Здесь описано, как устроен код и почему так. Запуск и команды: [README](../README.md), мобильное
приложение: [mobile/README.md](../mobile/README.md).

## Слои

```
src/
├── app/         # точка входа: провайдеры, роутер, глобальные стили
├── features/    # сценарии вне страниц (вход)
├── entities/    # общее для админки и кассы: kind (формы товара), product (разлив), shift, staff (роли)
├── pages/
│   ├── admin/   # layout (+ shell, home), warehouse (+ documents), catalog (+ giftRules), finance, staff, shifts, lib
│   └── pos/     # lib: логика кассы с тестами; ui: терминал и окна (+ receipt, payment, pour)
└── shared/      # api (клиент бэкенда), lib (деньги, форматирование, хуки), ui (кнопки, поля, модалки)
```

Импорты идут вниз: app, pages, features, entities, shared. Страницы друг друга не импортируют: код, нужный
и админке, и кассе, лежит в entities или shared. Между папками импорты идут через алиас `@/`, внутри папки относительные.

## Данные и сеть

- `shared/api/http.ts` хранит адрес бэкенда (`VITE_API_URL`). Мобильное приложение подменяет этот модуль по
  имени, поэтому импортировать его нужно строго как `@/shared/api/http`. При пустом `VITE_API_URL` запросы идут
  относительным путём, и `/api` проксирует dev-сервер (`vite.config.ts`): для туннеля хватает одного порта.
- `shared/api/core.ts`: `adminFetch` с JWT и обновлением токена, хелперы `post`, `put`, `del`, `qs`,
  `sortBody`, `archiveUrl`, `searchPaged` и `fetchSliced` (ответы Spring Page и Slice). Остальные файлы в
  `shared/api` разбиты по доменам, а `index.ts` собирает их вместе.
- Списки грузятся через `POST /search` с JSON-фильтром, бэкенд режет страницу до 200 записей.
- Бесконечные списки: `useInfiniteList` (`pages/admin/lib`) поверх `useInfiniteQuery`. Принимает ответ с
  числом страниц или только с признаком `hasNext` (журналы, где общее число не считается). Сводки над
  списком идут отдельным запросом, а не по загруженным страницам.
- Серверное состояние в TanStack Query. Ключи собирает `shared/api/queryKeys.ts`, производные ключи
  начинаются с корня сущности, чтобы инвалидировать по префиксу. После чека сбрасываются запросы, которые
  зависят от остатков (`STOCK_QUERY_KEYS` в `PosPage.tsx`); возврат, бронь, вскрытие флакона, продажа бланка
  и операции со сменой сбрасывают весь `['pos']`.

## Авторизация и роли

- JWT: короткий access в заголовке `Authorization`, refresh с ротацией. На 401 `adminFetch` один раз меняет
  refresh на новую пару и повторяет запрос. Параллельные 401 делят один обмен, иначе второй запрос
  получил бы "токен уже использован". Для `login` и `refresh` обмен не запускается. Если refresh не прошёл,
  токены стираются и бросается `UnauthorizedError`.
- Хранилище токенов подключаемое (`setTokenStorage`): в браузере localStorage, в приложении SecureStore.
- `entities/staff/roles.ts` содержит названия ролей, список назначаемых ролей и правило "кто открывает смену".
  Какие разделы админки видит роль, определяет `pages/admin/layout/shell/routeAccess.ts` (с тестом).

## Деньги

- Суммы хранятся в тыйынах (целые числа), вводятся и показываются в сомах. Конверсии и сумма строки
  считаются только в `shared/lib/money.ts`.
- Количество бывает дробным (миллилитры), а умножение во float теряет полтыйына. Поэтому количество
  переводится в тысячные доли, как `numeric(14,3)` на бэкенде, и умножается целыми с округлением HALF_UP.
  Формулы совпадают с `CostMath` бэкенда, тесты сверяют их с независимой реализацией на сетке количеств и цен.
- Скидка строки хранится суммой в тыйынах. Процент нужен только для ввода и показа.
- Знак сома рисуется вручную (`shared/ui/money.tsx`), потому что в шрифте его нет.

## Касса

Терминал `pages/pos/ui/PosPage.tsx` оркестрирует экран, а расчёты лежат в `pages/pos/lib` чистыми функциями.

| Модуль | Отвечает за |
|---|---|
| `rows.ts`, `totals.ts` | раскладка корзины по блокам чека, итоги: сумма до скидок, скидка чека, к оплате, подарки наборами |
| `discount.ts` | скидка чека процентом или суммой, раскладка по строкам целыми тыйынами (метод наибольших остатков) |
| `gifts.ts` | акции: условия И/ИЛИ, шаг кратности, потолок, счёт наборов |
| `payment.ts`, `paymentSplit.ts` | окно оплаты: сертификат идёт первым и не больше остатка; раскладка наличные/безнал/смешанная, сдача (редьюсер) |
| `stock.ts` | нехватка остатков суммарно по строкам одного товара: продавать в минус нельзя, оплата недоступна |
| `pour.ts`, `atomizers.ts`, `entities/product/dilution.ts` | распив: масло и флакон при доле масла (от 30 %), цена миллилитра спрея, решения при нехватке, пресеты объёма |
| `returns.ts`, `drafts.ts`, `reservations.ts` | возврат на полку по чеку; снапшот отложенного чека; строки брони с фиксированными ценами |
| `grouping.ts`, `payload.ts` | карточки витрины (модель и форма); строки чека и база порогов акций для запроса |
| `print.ts` | разметка чека и X-отчёта на ленту 80 мм с экранированием данных |

Состояние терминала: корзина, покупатель, скидка чека и значение `Overlay`. Это размеченное объединение,
которое говорит, какое окно открыто (оплата, варианты, объём распива, подарки, отложенные, брони, покупатель,
вскрытие, продажа бланка, выдача набора-подарка, X-отчёт, закрытие). Окна взаимоисключающие по построению.

Доменные правила (POS, подарки, сертификаты, распив, именование товара) описаны в `docs/` бэкенда.

## Админка

- Каркас `AdminLayout`: шапка с иконками модулей и меню профиля (смена пароля, тема, выход), слева рейл
  разделов. Касса открывается в том же каркасе и разворачивается на весь экран через `AdminChromeContext`.
- Списки строятся на `ListLayout` (пример: `BrandsPage`). Просмотр записи открывается вторым листом
  справа (`FastViewPortal`), страница отдаёт только содержимое.
- Документы склада (приёмка, корректировка, перемещение, продажа, возврат) используют один редактор
  `DocEditor` и список `DocList`. Различия между типами описаны в `docConfigs.ts`.
- Мутации страниц админки идут через `useEntityMutation` (инвалидация ключей, текст ошибки), активная
  плашка меню и чипов двигается через `useSlidingPill`.

## Оформление

- Две темы на одной разметке. Класс `dark` на `<html>` ставит `shared/lib/theme.ts`: по умолчанию тёмная,
  выбор хранится в localStorage, инлайн-скрипт в `index.html` применяет его до первой отрисовки.
- Значения токенов лежат CSS-переменными в `app/styles/index.css` (`:root` светлая тема, `.dark` тёмная).
  Компоненты используют только токены Tailwind из `tailwind.config.ts`: `brand` (смысловые цвета), `tint`
  (подложки превью), `glass` (панели, кнопки, таблицы), `surface` (карточки), `sheet` (лист под страницей).
- Шрифт Tenor Sans доработан под кыргызские буквы Ң, Ү, Ө. Суффикс `?v=3-kg` в адресе шрифта сбрасывает кэш
  старого файла.

## Общий код с мобильным приложением

Мобильная касса лежит в `mobile/` и берёт из `src/` всё, что не связано с вёрсткой браузера. Отдельный
репозиторий или пакет я не заводил: расчёты правятся в одном месте, а экраны у платформ свои.

- Metro (`mobile/metro.config.js`) резолвит `@/` в `../src`, а `~/` в `mobile/src`. Те же пути объявлены в
  `mobile/tsconfig.json`, там же исключены `pages/admin` и `pages/pos/ui`. Корневые `node_modules` скрыты:
  в вебе React 18, в приложении 19.
- Общие модули: `shared/api`, `pages/pos/lib`, `entities/product`, `entities/staff`, `shared/lib`
  (деньги, форматирование, телефон, формы товара). Состояние корзины у платформ своё (хук
  `pages/pos/ui/receipt/useReceipt.ts` и zustand-стор в `mobile/src/features/pos/cart.ts`), а расчёты общие.
- В общем коде три места учитывают мобильное приложение:
  1. `shared/api/core.ts`: хранилище токенов подключается через `setTokenStorage`.
  2. `entities/staff/roles.ts` не импортирует иконки и пути меню админки.
  3. `pages/pos/lib/print.ts` отдаёт только разметку: веб печатает её через iframe, приложение рендерит в PDF.
- `@/shared/api/http` в приложении заменён на `mobile/src/compat/http.ts`: в React Native нет
  `import.meta.env`, адрес берётся из `EXPO_PUBLIC_API_URL`.

## Тесты и проверки

- Vitest покрывает `pages/pos/lib`, `entities/product`, `shared/lib` и `routeAccess`. Тесты денег сверяют
  округление с независимой реализацией, раскладка скидки проверяется на случайных корзинах.
- `npm run lint`, `npm run typecheck`, `npm test` и `npm run build` запускает CI, мобильное приложение
  проверяется `npm run typecheck` в `mobile/`. UI автотестами не покрыт.
