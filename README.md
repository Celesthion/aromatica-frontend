# Aromatica

Склад и касса парфюмерного магазина: веб-админка, веб-касса и мобильная касса на Expo.
Это фронтенд. Бэкенд на Spring лежит в отдельном репозитории
`aromatica-backend`, обмен по REST.

## Что умеет система

- Касса: смена, витрина с карточками товаров, чек, скидки процентом или суммой, оплата наличными,
  безналом, смешанная и подарочным сертификатом, отложенные чеки, брони на покупателя, возвраты и
  сторно, X-отчёт, печать на ленту 80 мм.
- Распив и разлив: продажа по миллилитрам с выбором атомайзера и доли масла, вскрытие флакона у прилавка.
- Подарки по акциям с условиями И/ИЛИ, подарочные сертификаты с контрольной цифрой в коде.
- Админка: склад и документы (приёмки, корректировки, перемещения, продажи, возвраты), каталог
  (товары, модели, бренды, формы, акции), деньги и отчёты, сотрудники с ролями, смены, задачи.
- Мобильная касса для Android и iOS (папка `mobile/`).
- Светлая и тёмная темы.

Больше всего работы ушло на кассу. Все расчёты (суммы, скидки, налив, подарки, возвраты, оплата) я вынес
в чистые функции в `src/pages/pos/lib` и покрыл тестами, а экраны только показывают результат. Деньги
везде целые тыйыны, округление совпадает с бэкендом. Этот же код использует мобильная касса.

## Стек

React 18, TypeScript, Vite, TanStack Router и Query, Tailwind CSS, lucide-react, Vitest.
Мобильное приложение: Expo 54, React Native, expo-router, zustand.

## Запуск

Нужны Node 20 (версия в `.nvmrc`) и запущенный бэкенд.

```bash
npm install
npm run dev          # http://localhost:5173
```

Адрес бэкенда задаёт переменная `VITE_API_URL`, по умолчанию `http://localhost:8080`. Если задать её
пустой, запросы идут на тот же адрес, а dev-сервер проксирует `/api` на `localhost:8080`: так фронт
можно открыть через туннель, пробросив один порт 5173.

Остальные команды:

```bash
npm run build        # tsc -b и vite build, результат в dist/
npm run preview      # локальный просмотр сборки
npm start            # раздать dist через serve на порту из PORT
npm run typecheck
npm test
npm run lint
npm run format       # prettier --write; format:check только проверяет
```

Сборка статическая: хостингу нужно отдавать `index.html` на все пути (пример правила в `vercel.json`).
Мобильное приложение запускается отдельно, см. [mobile/README.md](mobile/README.md).

## Структура

```
src/
├── app/        # точка входа: провайдеры, роутер, глобальные стили
├── features/   # сценарии вне страниц (вход)
├── entities/   # общее для админки и кассы: форма товара, разлив, смена, роли
├── pages/
│   ├── admin/  # layout, warehouse, catalog, finance, staff, shifts, lib
│   └── pos/    # lib (логика кассы с тестами), ui (терминал и окна)
└── shared/     # api (клиент бэкенда), lib, ui
mobile/         # мобильная касса, использует код из src/ через алиас @/
docs/           # архитектура
```

Слои, работа с данными, устройство кассы и общий код с мобильным приложением описаны в
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Проверки

Перед коммитом: `npm run lint && npm run typecheck && npm test`, для мобильного приложения ещё
`npm run typecheck` в `mobile/`. То же запускает CI (`.github/workflows/ci.yml`), плюс `npm run build`.
