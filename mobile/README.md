# Aromatica: мобильная касса

Касса магазина для Android и iOS на Expo и React Native. Лежит в одном репозитории с вебом: расчёты,
клиент API и роли берутся из `../src`, а в приложении свои только экраны и оформление. Как устроен
общий код, описано в [docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md#общий-код-с-мобильным-приложением).

## Запуск

Общий код использует пакеты корня, поэтому сначала `npm install` в корне репозитория, потом в `mobile/`.

```bash
npm start            # Expo, QR-код для Expo Go
npm run web          # приложение в браузере, удобно смотреть вёрстку
npm run android      # сборка и запуск на устройстве или эмуляторе (нужен Android SDK)
npm run ios          # то же для iOS (нужен Xcode)
npm run typecheck
```

Линт и форматирование общие с вебом: `npm run lint` и `npm run format` в корне.

Адрес бэкенда задаёт `EXPO_PUBLIC_API_URL` в `mobile/.env` (файл не в репозитории, образец в `.env.example`).
В Expo Go на телефоне `localhost` недоступен, нужен адрес компьютера в локальной сети. Адрес рабочего
сервера в `.env` не указывайте: чек, пробитый при разработке, попадёт в его базу.

Проект на Expo SDK 54: Expo Go в магазинах приложений поддерживает только её. Для SDK 55 и выше нужен
собственный dev-клиент.

## Структура

```
app/                  # экраны (expo-router): _layout.tsx и (app)/ с меню, index, pos, shift, split
src/
├── compat/http.ts    # адрес бэкенда вместо import.meta.env веба
├── components/       # шапка, кнопка, поле, стекло, шторка, степпер, иконки, узор фона, ошибка запроса
├── features/
│   ├── auth/         # экран входа, сессия, хранилище токенов
│   ├── home/         # реестр плиток модулей на главной
│   └── pos/          # корзина, запросы, печать, шторки кассы, checkout/ (чек и оплата), receipts/ (чеки смены)
├── hooks/            # useTheme, useKeyboardHeight, useIsWide, useDebounced
└── theme.ts          # палитры светлой и тёмной темы
```

## Экраны и возможности

- Навигация: expo-router, выдвижное меню поверх экрана (кнопка и свайп от левого края).
- Вход и главная: приветствие, карточка смены с выручкой, плитки остальных модулей.
- Касса: каталог с поиском и фильтрами по форме, карточки (модель и форма) с остатком и ценой, выбор
  варианта, нижняя панель с меню, покупателем, чеком и поиском.
- Распив: отдельный экран `/split` с выбором объёма и атомайзера.
- Чек: на весь экран. Количество с потолком по остатку, скидка строки и чека, подарки по акциям,
  отложенные чеки (формат снапшота общий с вебом), брони с фиксацией цен, покупатель с историей покупок.
  Оплата наличными, безналом или смешанная идёт вторым шагом в том же окне.
- Смена: открытие со складом и наличными, X-отчёт, закрытие, возвраты и сторно по чекам смены.
- Печать: чек и X-отчёт рендерятся в PDF (expo-print) и уходят в системный диалог печати или в "Поделиться".
- Тема: светлая, тёмная или как в системе, выбирается в меню и сохраняется.

## Технические решения

- Токены палитры в обеих темах называются одинаково (`src/theme.ts`), экраны берут цвета из `useTheme()`.
  Заливка основной кнопки использует пару `primary` и `primaryText`: `ink` и `cream` в тёмной теме оба
  светлые, и текст пропал бы. Чек остаётся тёмной картой в обеих темах и берёт светлую палитру явно.
- Стекло (`Glass.tsx`) состоит из четырёх слоёв: размытие, подложка, светящийся верхний рант, тень у
  нижней кромки. В карточках каталога размытия нет: плиток до тридцати, и блюр в каждой роняет частоту
  кадров на слабом планшете.
- Картинки через `expo-image`: бэкенд отдаёт AVIF, штатный декодер Android теряет альфа-канал.
- Высоту клавиатуры меряем сами (`hooks/useKeyboardHeight.ts`): `KeyboardAvoidingView` не работает в модалках и в
  абсолютно позиционированных панелях.
- Распив вынесен на отдельный экран: на Android с новой архитектурой RN `Modal` не перерисовывается и не
  отдаёт фокус полю ввода.
- Нижний отступ каталога равен реальной высоте панели (`onLayout`), иначе нижний ряд не докручивается.
- Планшет определяется по короткой стороне экрана от 600 (порог `sw600dp`), на нём панель с подписями.
- `userInterfaceStyle: automatic` в `app.json`: тему выбирает приложение через `useColorScheme()`. Значение
  `light` отключило бы тёмную тему, если подключить `expo-system-ui`.
- Токены сессии лежат в SecureStore, профиль в AsyncStorage. Интерфейс хранилища в api-клиенте синхронный,
  поэтому значения держатся в памяти, а на диск пишутся в фоне.

## Сборка

Нужны JDK 21 и Android SDK (платформы 35 и 36), переменные `JAVA_HOME` и `ANDROID_HOME` указывают на них.
Версия приложения задаётся в `app.json` (`version` и `android.versionCode`).

```bash
export EXPO_PUBLIC_API_URL=https://api.example.com   # адрес вашего бэкенда
npx expo prebuild -p android      # только если менялся app.json
cd android && ./gradlew assembleRelease
```

APK появится в `android/app/build/outputs/apk/release/app-release.apk`. Подпись отладочным ключом: для
установки вручную этого достаточно, для магазина нужен собственный ключ. В релизной сборке обычный HTTP
отключён, адрес бэкенда должен быть https. Облачная сборка: профили в `eas.json`, адрес задаётся
переменной окружения EAS (`npx eas env:create --name EXPO_PUBLIC_API_URL`), затем
`npx eas build -p android --profile preview`.

## Ограничения

- Склад, продажи, каталог, финансы и кадры есть только в вебе, на главной они показаны плитками "Скоро".
- Подарочные сертификаты (оплата и продажа бланка) и вскрытие флакона доступны только в веб-кассе.
- Размытие на Android включено экспериментальным методом (`dimezisBlurView`), на части устройств оно
  выглядит как обычная полупрозрачная подложка.
